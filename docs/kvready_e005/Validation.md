黄区指用户执行实际机器测试的环境，完整定义见 [Requirements.md](Requirements.md)；P/D（提示词处理端与逐 token 生成端）的流程见 [Runbook.md](Runbook.md)。E005 的软件检查用于确认启动参数、请求路径和结果判据已经准备好，让黄区只执行一个固定批次。以下先给出检查证据，再记录文档自检与交叉评审；运行环境和证据边界集中在文末。

## 1. 主流程软件检查

17 项离线检查通过，覆盖配置中的卡号和端口实际传入子进程、P/D 资源分离、原生源码差异阻止构建复用、HTTP 错误保留、响应完整性、双分片完成计数、失败批次整体判定，以及只对自建进程组执行回收。

其中一项直接运行基线自带的 ucm/pd/toy_proxy_server.py，使用本地 HTTP（网络请求协议）服务代替两端推理服务：实测确认代理先向 P 发出一次非流式、单 token 请求，再向 D 发送原输入并转发 32 token 的流式响应。另一项直接检查失败请求成为 invalid 记录。

官方 Qwen3-4B 分词器实检确认：18 条输入均为 1024 token，18 个首块彼此独立，关闭思考模式的模板与完整结尾保留。这里的首块为前 128 个 token，对应运行配置的缓存块大小。

复现软件检查：

~~~powershell
uv --no-cache run --no-project --python 3.12 python -m unittest discover -s test/kvready_e005 -p 'test_offline.py' -v
~~~

主体源码由 Git 比较固定基线和交付分支；交付增量只位于 docs/kvready_e005 和 test/kvready_e005。5 个 Python 文件通过 Python 3.10 语法检查，Runbook 的 9 个 Bash 命令块通过语法检查。Requirements.md 附录 B 的用户原始消息与会话来源逐字一致，共 2771 个字符。
