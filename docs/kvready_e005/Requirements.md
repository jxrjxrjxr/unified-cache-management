# E005：原生 UCM 的 PD 分离基线需求

E005 要用 E004 修改前的 UCM（统一 KV 缓存管理）代码，在已有机器与镜像上完成一次 PD 分离流程和小规模性能采集，为 E004 的 HCCL 故障提供独立对照。PD 分离把提示词处理端 P 与逐 token 生成端 D 分开；HCCL 是昇腾集合通信库。以下依次说明实验交付、执行方式和结果判断，版本与原始要求集中保存在文末。

## 1. 实验交付

在已有个人 fork（GitHub 上的个人仓库副本）中从固定原生基线建立 kvready/e005 分支。交付只新增部署辅助脚本、专用测试与逐命令 Runbook；UCM 连接器、代理、存储及原生代码沿用基线。

采用已有的集中式 PD 示例：P 写入共享文件存储，D 读取后生成。P、D 各保留两卡张量并行，首轮使用 Qwen3-4B、1024 token 输入与 32 token 输出，执行 2 条预热、8 条串行和 8 条并发度为 2 的请求。该流程以默认通信条件完成基础检查与性能采集。

## 2. 执行与恢复

蓝区指 AI 承担实现与软件验证的工作环境，黄区指用户执行实际机器测试的环境。AI 端到端完成蓝区实现、有限软件验证、提交、推送和完整运行说明；用户在黄区取得代码、执行固定批次并手抄少量结果。

E005 使用同容器中的独立工作树，复用 E004 已有共享库与 Python 依赖。E004 的源码、现场选卡补丁、test 构建、运行配置、日志及 nids_aiv_ub 均保留。E005 子进程通过专属 Python 搜索路径选中自己的源码，批次结束回收自己的进程并返回 E004 原入口。

P 默认卡号为 3,5，D 为 6,7；卡号、HTTP 端口、vLLM 内部起始端口和 HCCL 可配置端口均通过配置显式传入。运行前展示最终值，运行记录保存实际值。

## 3. 结果判断

成功批次需要三个服务就绪、18 条完整响应、有限数值指标，以及 P 保存与 D 加载在两个张量并行分片上的完成计数。输出三行正常摘要，详细输入、响应、指标、启动日志和版本信息留在黄区。

首个失败结束固定批次，保留失败阶段、错误码与原始记录。恢复 E004 后再集中分析已有证据。E005 对同机文件存储路径的结果，为判断 HCCL 故障是否仍出现在原生流程提供依据。

# AI 输出风格约束与非量化评估准则

## 一、信息分级：先分清三层

1. **主认知层**——读者要建立的机制、判断与方法。占据正文，按认知顺序推进。

## 二、输出风格约束

### 约束一 · 标题树：同级同质、父子显式、可 BFS 遍历

- 标题构成一棵显式的树：父标题界定范围，子标题在父范围内并列展开。
- 同一父节点下的兄弟标题属于同一抽象层级、同一分类维度。
- 每个父标题下用一句话说明子标题之间的关系（导航句），读者由此知道这一层怎么展开。
- 只读某一层的标题，就能得到该层的完整画面；细节留给下一层。第一遍阅读是一次广度遍历。
- 层级数量按内容需要决定，能用一个层级讲清的，不制造下一个层级。

### 约束二 · 认知顺序：动机在前，元信息在后

- 文档要回答的问题出现在开头，读者由此知道每一节为何存在。

- 需要指出某条路径不成立时，说出成立的范围、替代解释或成立条件。
- 例外只有一类：用户明确要求纠错、风险提示或安全边界说明时，直接指出问题本身。

### 约束四 · 术语锚定：首用即定义

- 同级条目同质：一条要点承载一件事；需要声明"这两处不同"时，说明它应当拆分。

判定只给结论，不折算分数，依据是原文引用。

### 准则一 · 标题树

- 检查问题：只读某一层的标题，能否得到该层的完整画面？兄弟标题是否同质？每个父标题下是否有导航句？

- 修改方向：补导航句、把不同质的标题拆到不同父节点、把非标题层级的内容降为正文。

### 准则二 · 认知顺序

- 检查问题：文档要回答的问题是否出现在开头？元信息是否集中在文末？

### 准则三 · 表达基调

### 准则四 · 术语锚定

- 检查问题：术语首用处是否给出定义或指向？是否存在只在此次对话中有意义的指代？
